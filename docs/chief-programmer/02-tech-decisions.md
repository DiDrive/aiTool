# 技术决策

1. 采用 sidecar，不做 React 到 Vue 的逐组件移植。原因是上游包含完整后端、认证、
   存储和生成任务，直接移植会形成长期分叉。
2. 同时提供 external 模式。它让 Docker/服务器实例可立即联调，也提供本地运行包缺失
   时的可用路径。
3. 本地服务使用动态端口和 `127.0.0.1`。上游当前 Go 入口监听所有网卡，发布用 fork
   必须增加 `BIND_ADDRESS` 支持，不能只靠启动环境变量声明。
4. 不在 Vue 页面中使用 iframe。独立 `BrowserWindow` 可避免 CSP、拖放和快捷键冲突，
   也能明确隔离 Node 权限。
5. AGPL 组件与 Apache-2.0 工作台保持进程和源码边界。分发包仍必须履行 AGPL 的源码、
   许可证及修改说明义务；此边界不是规避许可证义务的手段。
6. 复用上游 Canvas Agent 的 `script/breakdown/references/storyboard/video` 阶段与真实节点
   工具，只补工作台文本模型桥接。文本模型使用通用 OpenAI 兼容协议，图片和视频仍走
   PIX、KWJM、ExchangeToken、ModelTop 或自定义平台各自的协议适配。
7. 专用创作节点采用“现有节点类型 + `workflowKind`”的兼容模型，不扩展持久化枚举。
   这样旧画布可直接打开，现有任务轮询、素材存储、导入导出和连线算法无需分叉。
8. 剧本与分镜脚本继续复用现有文本模型执行器。节点内“AI 生成”是主入口，生成后的
   正文仍保留可编辑能力，用于人工修订而不是代替 AI 生成流程。
9. 结构化剧本/分镜采用节点 metadata 内的版本兼容字段，不建立独立数据库。AI 文本输出
   要求 JSON，解析失败时降级为单场或逐行镜头，保证旧画布仍能打开详情。
10. 素材是否齐全通过 `assetNodeIds` 指向的真实节点内容计算。禁止只写布尔完成标志，避免
    删除、上传替换或生成失败后状态失真。
11. 非 JSON 或字段不完整的模型输出不得直接伪装成场次/镜头表。原文完整保存在
    `workflowRawText`，并以原文模式展示；生成链路自动执行一次结构修复，只有通过必填
    字段校验后才设置 `workflowStructureValid=true`。
12. 剧本、分镜脚本及素材描述的业务内容统一使用简体中文。结构校验除字段完整性外还
    校验中文内容；英文结果进入结构修复并翻译为中文，必要专有名词可在中文后保留英文。
13. 镜头素材换绑采用“镜头元数据 + 受管依赖连线”同步提交。只删除上一版和当前版绑定
    节点与对应分镜图/视频间的受管连线，保留用户创建的其他无关连线；重复素材仍被其他
    槽位使用时不得误删。
14. 分镜图必须提交全部已绑定素材，不允许静默裁剪或转成文生图。PIX 协议按平台真实
    契约转换：1 张参考图使用 `image-edit`，2 张及以上使用 `multi-reference`；GPT Image 2
    超过真实上限 16 张时直接返回明确错误，由用户调整绑定。
15. 本地模型渠道 ID 不能只按能力使用固定默认值。每次请求必须确认首选渠道的 `models`
    包含当前模型；不包含时自动选择声明该模型的同步渠道，避免模型切换后仍发往旧渠道。
16. 视频倒推剧情不能把视频 URL 当普通文本上下文。视频先按非破坏分析区间解码，再使用
    分片、自适应候选帧和近似帧去重形成视觉证据；不可见或未转写的对白禁止推测。视频
    解码失败必须中止并提示，不能返回与视频无关的猜测剧本。
17. 视频裁剪与分析范围分离保存，均不覆盖或转码原视频。播放和倒推使用范围元数据；只有
    导出或上游接口不支持区间时才生成实体片段。
18. 原片倒推和梗概改编是两个版本域。原片时间轴是只增不覆盖的事实底稿；人物、场景、
    台词替换及剧情梗概生成新的改编剧本和分镜脚本节点。
19. 视频倒推采用证据优先结构：场次/镜头保存起止毫秒与证据时间码；人物、场景、风格
    形成独立一致性档案，后续素材与逐镜生成引用稳定 ID，避免每镜重新猜测。
